## Problem Statement

You have a function `printNumber` that can be called with an integer parameter and prints it to the console.
- For example, calling `printNumber(7)` prints 7 to the console.

You are given an instance of the class `ZeroEvenOdd` that has three functions: `zero`, `even`, and `odd`. The same instance of `ZeroEvenOdd` will be passed to three different threads:

- **Thread A**: calls `zero()` that should only output 0's.
- **Thread B**: calls `even()` that should only output even numbers.
- **Thread C**: calls `odd()` that should only output odd numbers.

Modify the given class to output the series `"010203040506..."` where the length of the series must be `2n`.

Implement the `ZeroEvenOdd` class:

- `ZeroEvenOdd(int n)` Initializes the object with the number n that represents the numbers that should be printed.
- `void zero(printNumber)` Calls printNumber to output one zero.
- `void even(printNumber)` Calls printNumber to output one even number.
- `void odd(printNumber)` Calls printNumber to output one odd number.

**Example 1:**

- **Input:** n = 2
- **Output:** "0102"
- **Explanation:** There are three threads being fired asynchronously.
One of them calls zero(), the other calls even(), and the last one calls odd().
"0102" is the correct output.

**Example 2:**

- **Input:** n = 5
- **Output:** "0102030405"


## Solution 1: Synchronization using Monitor

With Monitor, all three threads share a single lock. We will use a state variable called `_turn` to dictate the current state (0 = Zero's turn, 1 = Odd's turn, 2 = Even's turn). We also need a shared `_current` variable to track the number we are on.

```csharp
public class ZeroEvenOdd {
    private int n;
    private readonly object _lock = new object();
    
    // 0 = Zero's turn, 1 = Odd's turn, 2 = Even's turn
    private int _turn = 0; 
    private int _current = 1;

    public ZeroEvenOdd(int n) {
        this.n = n;
    }

    public void Zero(Action<int> printNumber) {
        for (int i = 1; i <= n; i++) {
            lock (_lock) {
                while (_turn != 0) {
                    Monitor.Wait(_lock);
                }
                
                printNumber(0);
                
                // If the number we are about to print is odd, it's Odd's turn. Else, Even's turn.
                _turn = (_current % 2 != 0) ? 1 : 2;
                
                Monitor.PulseAll(_lock); // Wake up everyone
            }
        }
    }

    public void Even(Action<int> printNumber) {
        for (int i = 2; i <= n; i += 2) {
            lock (_lock) {
                while (_turn != 2) {
                    Monitor.Wait(_lock);
                }
                
                printNumber(_current);
                _current++; // Move to the next number
                
                _turn = 0; // It's always Zero's turn after a number is printed
                
                Monitor.PulseAll(_lock);
            }
        }
    }

    public void Odd(Action<int> printNumber) {
        for (int i = 1; i <= n; i += 2) {
            lock (_lock) {
                while (_turn != 1) {
                    Monitor.Wait(_lock);
                }
                
                printNumber(_current);
                _current++; // Move to the next number
                
                _turn = 0; // Back to Zero's turn
                
                Monitor.PulseAll(_lock);
            }
        }
    }
}
```

**Detailed Explanation:**

1. **The Turn Variable** (`_turn`): We strictly enforce the sequence. `Zero()` always sets the turn to 1 or 2 depending on _current. `Even()` and `Odd()` always reset the turn back to 0 after they do their work.

2. **The Current Number** (`_current`): Because the state is shared, Even and Odd rely on the shared `_current` variable to know what to print, and they are responsible for incrementing it so Zero knows what to do next.

3. **PulseAll Necessity**: When Zero finishes and sets `_turn = 2`, it calls `PulseAll()`. This wakes up both Even and Odd. Odd checks the while loop, sees `_turn != 1`, and immediately goes back to sleep, releasing the lock so Even can proceed.


## Solution 2: Synchronization using SemaphoreSlim

With SemaphoreSlim, we need three semaphores. `Zero` always starts first, so it gets the initial ticket. `Zero` is the "dispatcher"—after it prints, it looks at the current number to decide whether to give a ticket to `Odd` or `Even`.

```csharp
using System;
using System.Threading;

public class ZeroEvenOdd {
    private int n;
    
    // Zero starts with 1 permit to kick off the sequence
    private SemaphoreSlim _zeroSem = new SemaphoreSlim(1, 1);
    private SemaphoreSlim _oddSem = new SemaphoreSlim(0, 1);
    private SemaphoreSlim _evenSem = new SemaphoreSlim(0, 1);

    public ZeroEvenOdd(int n) {
        this.n = n;
    }

    public void Zero(Action<int> printNumber) {
        for (int i = 1; i <= n; i++) {
            _zeroSem.Wait(); // Wait for permission to print 0
            
            printNumber(0);
            
            // Dispatcher logic: Who gets the baton next?
            if (i % 2 != 0) {
                _oddSem.Release(); // Wake up Odd
            } else {
                _evenSem.Release(); // Wake up Even
            }
        }
    }

    public void Even(Action<int> printNumber) {
        // Even numbers start at 2 and increment by 2
        for (int i = 2; i <= n; i += 2) {
            _evenSem.Wait(); // Wait for Zero to pass the baton here
            
            printNumber(i);
            
            // Hand the baton back to Zero
            _zeroSem.Release();
        }
    }

    public void Odd(Action<int> printNumber) {
        // Odd numbers start at 1 and increment by 2
        for (int i = 1; i <= n; i += 2) {
            _oddSem.Wait(); // Wait for Zero to pass the baton here
            
            printNumber(i);
            
            // Hand the baton back to Zero
            _zeroSem.Release();
        }
    }
}

```

**Detailed Explanation:**
1. **The Dispatcher**: The `Zero()` method acts as a traffic cop. Because it loops exactly n times and increments i, it always knows exactly whose turn is next.

2. **Predictable Loops**: We know exactly how many times `Even` and `Odd` will run. By using i += 2, we don't need any shared state variables to track the current number—the for loop handles it natively!
