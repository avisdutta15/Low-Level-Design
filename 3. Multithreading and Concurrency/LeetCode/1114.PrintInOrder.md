## Problem Statement

Suppose we have a class:

```csharp
public class Foo {
  public void first() { print("first"); }
  public void second() { print("second"); }
  public void third() { print("third"); }
}
```

The same instance of Foo will be passed to three different threads. `Thread A` will call `first()`, `Thread B` will call `second()`, and `Thread C` will call `third()`. Design a mechanism and modify the program to ensure that `second()` is executed after `first()`, and `third()` is executed after `second()`.

Note:

We do not know how the threads will be scheduled in the operating system, even though the numbers in the input seem to imply the ordering. The input format you see is mainly to ensure our tests' comprehensiveness.

**Example 1:**

- **Input:** nums = [1,2,3]
- **Output:** "firstsecondthird"
- **Explanation:** There are three threads being fired asynchronously. The input [1,2,3] means thread A calls first(), thread B calls second(), and thread C calls third(). "firstsecondthird" is the correct output.

**Example 2:**

- **Input:** nums = [1,3,2]
- **Output:** "firstsecondthird"
- **Explanation:** The input [1,3,2] means thread A calls first(), thread B calls third(), and thread C calls second(). "firstsecondthird" is the correct output.
 

**Constraints:**
nums is a permutation of [1, 2, 3].


## Solution 1: Synchronization using Monitor
```csharp
using System.Threading;

public class Foo {

    private readonly object _lock = new object();       // lock
    private int turn = 1;                               // shared state

    public Foo() {
        
    }

    public void First(Action printFirst) {
        lock(_lock){
            // printFirst() outputs "first". Do not change or remove this line.
            printFirst();

            turn = 2;                   // Update state
            Monitor.PulseAll(_lock);    // Wake up waiting threads
        }        
    }

    public void Second(Action printSecond) {
        lock(_lock){
            while(turn!=2){
                Monitor.Wait(_lock);    // Sleep and release lock
            }
            
            // printSecond() outputs "second". Do not change or remove this line.
            printSecond();

            turn = 3;
            Monitor.PulseAll(_lock);
        }        
    }

    public void Third(Action printThird) {        
        lock(_lock){
            while(turn!=3){
                Monitor.Wait(_lock);    // Sleep and release lock
            }
            
            // printThird() outputs "third". Do not change or remove this line.
            printThird();
        }
    }
}
```


Unlike `SemaphoreSlim` or `AutoResetEvent`—which have "memory" of a signal being sent—`Monitor` signals are fleeting. If a thread calls Pulse and no one is listening, that signal is lost forever. Because of this, `Monitor` always requires a shared state variable (in our case, _step) to track what is actually happening.

Here is a detailed, step-by-step breakdown of the mechanics.

**1. The Setup**
- `_lock`: An object used exclusively for synchronization. `Monitor.Wait` and `Monitor.PulseAll` must be called from inside a `lock(_lock)` block. If they aren't, the compiler throws a `SynchronizationLockException`.

- `_step`: An integer initialized to 1. This acts as our source of truth for whose turn it is.

**2. The Execution Flow (Worst-Case Scenario)**

To see the magic of `Monitor`, let's imagine the worst-case scenario: The OS schedules Thread 3 first, then Thread 2, and finally Thread 1.

**Step A: Thread 3 Arrives First**

1. Thread 3 enters `Third()`. It acquires the `lock (_lock)`.
2. It evaluates the while loop: `while (_step != 3)`. Since `_step` is currently 1, the condition is true.
3. Thread 3 calls Monitor.Wait(_lock).
4. `The Magic:` Wait does two things atomically: it puts Thread 3 to sleep (into a "Wait Queue"), and it immediately releases the lock. If it didn't release the lock, the program would deadlock right here!

**Step B: Thread 2 Arrives Second**

1. Thread 2 enters `Second()`. Because Thread 3 released the lock, Thread 2 can acquire `lock (_lock)`.
2. It evaluates its while loop: `while (_step != 2)`. Since _step is still 1, the condition is true.
3. Thread 2 calls `Monitor.Wait(_lock)`. It goes to sleep in the Wait Queue and releases the lock.

**Step C: Thread 1 Finally Arrives**

1. Thread 1 enters `First()`. It acquires the `lock (_lock)`.
2. It executes `printFirst()`. (Output: "first").
3. It updates the state: `_step = 2`.
4. It calls `Monitor.PulseAll(_lock)`.
5. Thread 1 exits the lock block.

**3. The Re-awakening (`PulseAll` and the `while` loop)**

When Thread 1 calls `PulseAll`, it takes Thread 2 and Thread 3 out of the "Wait Queue" and moves them to the "Ready Queue". They both wake up, but only one can re-acquire the lock at a time to continue.

Let's say the OS randomly gives the lock back to Thread 3 first:
1. Thread 3 wakes up and re-acquires the lock.
2. It resumes execution exactly where it left off, which is inside the while loop.
3. Crucial check: It re-evaluates the condition while `(_step != 3)`. Because _step is only 2, the condition is still true.
4. Thread 3 calls `Monitor.Wait(_lock)` again! It goes back to sleep and releases the lock. (This is why we MUST use a while loop and not an if statement. Thread 3 woke up, but it still wasn't its turn).

Now the lock is free again, so Thread 2 grabs it:
1. Thread 2 wakes up and re-acquires the lock.
2. It re-evaluates `while (_step != 2)`. Because _step is now 2, the loop exits!
3. Thread 2 executes `printSecond()`. (Output: "second").
4. It updates the state: `_step = 3`.
5. It calls `Monitor.PulseAll(_lock)`. This wakes up Thread 3 again.
6. Thread 2 exits the lock block.

Finally, Thread 3 gets the lock back:
1. It re-evaluates `while (_step != 3)`. _step is now 3, so the loop exits.
2. Thread 3 executes `printThird()`. (Output: "third").

Summary of the Mechanics
- `lock`: Protects the _step variable from being read/written by multiple threads simultaneously.
- `Wait()`: Says, "It's not my turn. I'll give up the lock and go to sleep until someone taps me on the shoulder."
- `PulseAll()`: Says, "I changed the state! Everyone wake up and check if it's your turn now."
- `while loop`: Protects against waking up out of order (or "spurious wakeups" caused by the OS). It forces the thread to verify the state before proceeding.

## Solution 2: Synchronization using SemaphoreSlim

```csharp
using System.Threading;
public class Foo {
    // Initialize with 0 available permits, max 1.
    // Threads will block immediately if they call Wait().
    private readonly SemaphoreSlim _gate12 = new SemaphoreSlim(0, 1);
    private readonly SemaphoreSlim _gate23 = new SemaphoreSlim(0, 1);

    public Foo() {
        
    }

    public void First(Action printFirst) {
        
        // printFirst() outputs "first". Do not change or remove this line.
        printFirst();

        // Adds 1 permit, allowing Second() to pass through.
        _gate12.Release();
    }

    public void Second(Action printSecond) {
        // Blocks until First() releases a permit.
        _gate12.Wait();

        // printSecond() outputs "second". Do not change or remove this line.
        printSecond();

        // Adds 1 permit, allowing Third() to pass through.
        _gate23.Release();
    }

    public void Third(Action printThird) {
        // Blocks until Second() releases a permit.
        _gate23.Wait();

        // printThird() outputs "third". Do not change or remove this line.
        printThird();
    }
}
```

**How it works step-by-step:**
Think of a `SemaphoreSlim` like a bucket of tickets (permits).

- When we declare `new SemaphoreSlim(0, 1)`, we are saying: "*Start with 0 tickets in the bucket, and the bucket can hold a maximum of 1 ticket.*"
- `Wait()` means "*Take a ticket from the bucket.*" If the bucket is empty (0 tickets), the thread goes to sleep until a ticket is available.
- `Release()` means "*Put a ticket into the bucket.*"

**The Execution Flow:**

1. Imagine Thread 3 (running `Third()`) starts first. It hits `_sem23.Wait()`. Because the bucket has 0 tickets, Thread 3 goes to sleep.
2. Next, Thread 2 (running `Second()`) starts. It hits `_sem12.Wait()`. Because its bucket also has 0 tickets, Thread 2 goes to sleep.
3. Finally, Thread 1 (running `First()`) starts. It doesn't have to wait for anything! It executes `printFirst()`.
4. Thread 1 then calls `_sem12.Release()`. This puts 1 ticket into the `_sem12` bucket.
5. Thread 2 instantly wakes up, grabs that ticket (reducing the bucket back to 0), and executes `printSecond()`.
6. Thread 2 then calls `_sem23.Release()`. This puts 1 ticket into the `_sem23` bucket.
7. Thread 3 instantly wakes up, grabs that ticket, and executes `printThird()`.
