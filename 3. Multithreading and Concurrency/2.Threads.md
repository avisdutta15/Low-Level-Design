# 1. Creating Threads and Passing Data

There are three primary ways to initialize a thread and send data into its execution path.

### A. ThreadStart (No Parameters)

The simplest way, used when the method requires no arguments and returns no value.

```csharp
static void MyMethod(){
    # Body
}
Thread t = new Thread(new ThreadStart(MyMethod));
# Thread t = new Thread(MyMethod); # Simiplified    
t.Start();

# The signature of MyMethod should follow:
# public delegate void ThreadStart();
```

### B. ParameterizedThreadStart (Object Parameter)

A legacy way to pass exactly one object. It requires casting inside the method.

```csharp
# The signature of ParameterizedThreadStart is :
# public delegate void ParameterizedThreadStart(object? obj);

Thread t = new Thread(new ParameterizedThreadStart(DoWork));
t.Start("Hello World"); // Passes string as object

static void DoWork(object data) {
    string message = (string)data; // Manual casting required
    Console.WriteLine(message);
}
```

### C. Lambda Expressions (Modern Standard)

The most flexible approach. It allows you to pass multiple strongly-typed variables via "closures."

```csharp
public static void Test(){}
public static void ProcessUser(int id, string name){}

int id = 42;
string name = "Worker1";

Thread t1 = new Thread(()=>Test());
# or Thread t1 = new Thread(Test);
Thread t2 = new Thread(() => ProcessUser(id, name));
t2.Start();
```

## 2. Pausing and Interrupting Threads

### Pausing (Thread.Sleep)

Suspends the current thread for a specified time. `Thread.Sleep(0)` or `Thread.Yield()` can be used to voluntarily give up the thread's remaining time slice to other threads.

### Interrupting (Thread.Interrupt)

If a thread is in a "`waiting`" state (e.g., `Thread.Sleep`, `Join`, or `Wait`), calling `Interrupt()` on it forces it to wake up by throwing a `ThreadInterruptedException`.

Use Case: Waking up a background worker early to shut it down.

```csharp
public class Example
{
    public static void Main()
    {
        // Interrupt a sleeping thread.
        var sleepingThread = new Thread(SleepIndefinitely);
        sleepingThread.Name = "Sleeping";
        sleepingThread.Start();
        Thread.Sleep(2000);
        sleepingThread.Interrupt();
        sleepingThread.Join();
    }

    private static void SleepIndefinitely()
    {
        Console.WriteLine($"Thread '{Thread.CurrentThread.Name}' about to sleep indefinitely.");
        try
        {
            Thread.Sleep(Timeout.Infinite);
        }
        catch (ThreadInterruptedException)
        {
            Console.WriteLine($"Thread '{Thread.CurrentThread.Name}' awoken.");
        }
        finally
        {
            Console.WriteLine($"Thread '{Thread.CurrentThread.Name}' executing finally block.");
        }
        Console.WriteLine($"Thread '{Thread.CurrentThread.Name}' finishing normal execution.");
        Console.WriteLine();
    }
}
// The example displays the following output:
//       Thread 'Sleeping' about to sleep indefinitely.
//       Thread 'Sleeping' awoken.
//       Thread 'Sleeping' executing finally block.
//       Thread 'Sleeping' finishing normal execution.
```

## 3. Foreground and Background Threads

- Foreground Threads
  - Created by default - `new Thread()`.
  - Runs until its task gets finished. Does not depend on the main thread.
  - Used to perform application critical tasks.

```csharp
Thread t = new Thread(Test){
    Name = "Foreground Thread"
};
```
- Background Threads
  - Lifetime depends on the Foreground Thread of the application.
  - Runs till the main thread or till all the Foreground Threads are runnning.
  - Used to perform support / book keeping operations. 

```csharp
Thread t = new Thread(Test){
    IsBackground = true;
    Name = "Background Thread"
};
```
## 4. Cancelling Threads
In older versions of .NET, developers used `Thread.Abort()` to forcefully kill a thread. This was an architectural nightmare. It would stop the thread dead in its tracks, leaving database connections open, lock blocks permanently locked, and application state corrupted. Modern .NET completely removes `Thread.Abort()`.

Instead, modern .NET uses **Cooperative Cancellation**. You cannot force a task to stop; you can only ask it to stop, and it is the task's responsibility to listen and shut down gracefully.

**1. The Two Halves of Cancellation**

- **CancellationTokenSource (The Controller):** 

    This is the object that owns the cancellation logic. It is mutable. You call `cts.Cancel()` on this object.

- **CancellationToken (The Listener):** 

    This is a lightweight, read-only struct that you extract from the source (`cts.Token`) and pass down to your worker threads or tasks. 
    
    Workers can only read its state; they cannot trigger a cancellation themselves.
    - Cancallation by polling - // If the token is cancelled, this immediately throws an `OperationCanceledException`.

        For Tasks - `ct.ThrowIfCancellationRequested();`

        For Threads - `ct.IsCancellationRequested`

    - Cancellation by registering Callback
    
      `using var registration = ct.Register(() => 
        { //Cleanup logic
        });`
    - Passing to underlying async APIs

        `await Task.Delay(1000, ct);`

In a microservices or complex backend architecture, cancellation should cascade.
If a user hits an ASP.NET Web API endpoint to generate a massive report, and then closes their browser tab 5 seconds later, the framework automatically triggers the HttpContext.RequestAborted cancellation token.

If you pass that token into your Business Layer, and your Business Layer passes it into Entity Framework, the moment the user closes their browser, the SQL query executing on your database server is instantly killed. This saves massive amounts of compute and database DTUs.

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

public class CancellationDemo
{
    public static async Task Main()
    {
        // 1. The Controller
        using var cts = new CancellationTokenSource();
        
        // Safety net: Automatically cancel after 3.5 seconds
        cts.CancelAfter(TimeSpan.FromMilliseconds(3500));

        Console.WriteLine("Starting background work. Press 'c' to cancel manually.");

        // 2. Pass the read-only Token down to the worker
        Task workerTask = ProcessDataAsync(cts.Token);

        // A side-task just to listen for manual user input
        _ = Task.Run(() => {
            if (Console.ReadKey(true).KeyChar == 'c') {
                Console.WriteLine("\n[Main] Manual cancellation requested!");
                cts.Cancel(); // Triggers the token
            }
        });

        try 
        {
            // Wait for the worker to finish or cancel
            await workerTask;
            Console.WriteLine("Work completed successfully.");
        }
        catch (OperationCanceledException) 
        {
            // This is the EXPECTED exception when cooperative cancellation succeeds.
            Console.WriteLine("Work was gracefully cancelled. System state is clean.");
        }
    }

    // The Worker Method
    static async Task ProcessDataAsync(CancellationToken ct)
    {
        // METHOD 1: The Callback (Triggered immediately when Cancel() is called)
        // Great for unblocking legacy synchronous code or cleaning up native handles.
        using var registration = ct.Register(() => 
        {
            Console.WriteLine("[Cleanup] Token tripped! Releasing native resources...");
        });

        for (int i = 0; i < 10; i++)
        {
            // METHOD 2: Polling (The manual check)
            // If the token is cancelled, this immediately throws an OperationCanceledException
            ct.ThrowIfCancellationRequested(); 

            Console.WriteLine($"[Worker] Processing chunk {i}...");

            // METHOD 3: Passing to underlying async APIs
            // Framework methods like Task.Delay, HttpClient.GetAsync, or SqlCommand.ExecuteReaderAsync 
            // natively monitor the token and will safely abort their own internal work.
            await Task.Delay(1000, ct); 
        }
    }
}
```

## 5. Exception Handling in Threads

Critical Rule: Exceptions in a thread do not bubble up to the Main thread. If a background thread crashes and the exception is unhandled, the entire process usually terminates.

You must use a try-catch block inside the thread's delegate:
```csharp
Thread t = new Thread(() => {
    try {
        // Dangerous work
    } catch (Exception ex) {
        // Log locally or update a shared error state
        Console.WriteLine($"Thread failed: {ex.Message}");
    }
});
```

## 6. Threads Returning Data / Results
The Thread class does not have a return value. To get data back, you have two options:

**Option A: Shared Object / Variable**

```csharp
string result = "";
Thread t = new Thread(() => {
    result = "Data from thread";
});
t.Start();
t.Join(); 
Console.WriteLine(result);
```

**Option B: Callback Method**

```csharp
void StartWork() {
    Thread t = new Thread(() => {
        var data = DoWork();
        OnWorkComplete(data); // Call back to main logic
    });
    t.Start();
}

void OnWorkComplete(string result) {
    Console.WriteLine($"Received: {result}");
}
```
