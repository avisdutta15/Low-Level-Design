## 1. lock (The Syntactic Sugar)
**Speed:** Fast (Hybrid).

**Scope:** Single Process.

**Methods:** None (It is a C# language keyword, not a class).

**Puts Thread to Sleep?:** **Yes**. It spins in user-mode for a few cycles, and if the lock is still held, it surrenders to the OS kernel and puts the thread to sleep.

**Best For:** 95% of everyday thread-safety needs. Clean, readable, and prevents you from accidentally forgetting to release the lock.

**Usage Example:**
```csharp
private readonly object _syncRoot = new object();

public void SafeUpdate() 
{
    lock (_syncRoot) 
    {
        // Critical section
    }
}
```

## 2. Monitor (The Engine Underneath)

**Speed:** Fast (Hybrid).

**Scope:** Single Process.

**Methods:** `Enter()`,` Exit()`, `TryEnter()`, `Wait()`, `Pulse()`, `PulseAll()`.

**Puts Thread to Sleep?:** **Yes.** (Same behavior as lock, because lock literally compiles down to Monitor).

**Best For:** When you need a timeout (TryEnter(TimeSpan)) to avoid infinite deadlocks, or when you need threads to talk to each other (using Wait() to sleep until another thread calls Pulse()).

**Usage Example:**

```csharp
private readonly object _syncRoot = new object();

public void UpdateWithTimeout() 
{
    bool lockTaken = false;
    try 
    {
        // Wait max 1 second for the lock
        Monitor.TryEnter(_syncRoot, TimeSpan.FromSeconds(1), ref lockTaken);
        if (lockTaken) 
        {
            // Critical section
        }
    }
    finally 
    {
        if (lockTaken) Monitor.Exit(_syncRoot);
    }
}
```

## 3. Mutex (The OS Heavyweight)

**Speed:** Very Slow (Requires a context switch from User Mode to OS Kernel Mode).

**Scope:** Cross-Process / Machine-wide (If given a string name).

**Methods:** `WaitOne()`, `ReleaseMutex()`, `OpenExisting()`.

**Puts Thread to Sleep?:** **Yes** (Kernel-level sleep).

**Best For:** Inter-Process Communication (IPC). Ensuring only one instance of an application is running, or preventing two separate microservices on the same VM from writing to the same local file.

**Usage Example:**
```csharp
// The string name registers this lock at the Operating System level
using var mutex = new Mutex(false, "Global\\MyUniqueAppMutex");

if (mutex.WaitOne(TimeSpan.FromSeconds(3))) 
{
    try 
    {
        // Machine-wide critical section
    }
    finally 
    {
        mutex.ReleaseMutex();
    }
}
```

**Named Mutex:** By giving it a name (starting with `Global\`), you can prevent two different instances of your `.exe` from running at the same time.

```csharp
// Example: Allowing only one instance of an app to run
using (var mutex = new Mutex(false, "Global\\MyUniqueAppName")) {
    if (!mutex.WaitOne(0, false)) {
        Console.WriteLine("Another instance is already running!");
        return;
    }
    // Run application logic here
}
```

## 4. SpinLock (The Micro-Optimizer)

**Speed:** Ultra Fast (But dangerous).

**Scope:** Single Process.

**Methods:** `Enter()`, `Exit()`, `TryEnter()`.

**Puts Thread to Sleep?:** **No**. It continuously loops (spins) and burns CPU cycles until the lock opens.

**Best For:** Extreme low-latency environments (like High-Frequency Trading) where the critical section is guaranteed to take less time than the cost of an OS context switch (~1-2 microseconds).

**Usage Example:**
```csharp
// Note: SpinLock is a struct, not a class. Do not pass it by value!
private SpinLock _spinLock = new SpinLock(false);

public void HighFrequencyUpdate() 
{
    bool lockTaken = false;
    try 
    {
        _spinLock.Enter(ref lockTaken);
        // CRITICAL: Must be insanely fast (e.g., simple math only)
    }
    finally 
    {
        if (lockTaken) _spinLock.Exit(false);
    }
}
```
