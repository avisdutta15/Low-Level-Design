# 4. Interface Segregation Principle (ISP)

## 1. What is it?

**"Clients should not be forced to depend upon interfaces that they do not use."**

In simpler terms: Do not create massive, "fat" interfaces that contain a dozen different methods if a class only needs to use one or two of them. Instead, break that large interface down into smaller, highly cohesive, specific interfaces.

## 2. Why is it needed?

* **Reduces Code Bloat:** If a class is forced to implement a giant interface, the developer has to write empty methods or throw exceptions for the methods they don't care about.

* **Reduces Coupling:** If an interface has 10 methods, and you change the signature of just one method, every single class that implements that interface must be recompiled and updated, even if they never use that specific method.

* **Better Intent:** Smaller interfaces clearly communicate what a class is capable of doing.

## 3. Code Example in C# (The Violation)

A classic violation of ISP happens when we create a "catch-all" interface for employees.

Imagine we have a system that manages daily tasks for our staff. We create a single `IEmployee` interface for everyone.

```csharp
using System;

// The "Fat" Interface
public interface IEmployee
{
    void WriteCode();
    void AttendMeetings();
    void ConductPerformanceReview();
}

// A Manager does all of these things perfectly.
public class Manager : IEmployee
{
    public void WriteCode() => Console.WriteLine("Reviewing architecture and coding...");
    public void AttendMeetings() => Console.WriteLine("Attending strategy meetings...");
    public void ConductPerformanceReview() => Console.WriteLine("Reviewing team performance...");
}

// The Violation: A Junior Developer doesn't conduct reviews!
public class JuniorDeveloper : IEmployee
{
    public void WriteCode() => Console.WriteLine("Writing C# code...");
    public void AttendMeetings() => Console.WriteLine("Attending daily standup...");

    public void ConductPerformanceReview()
    {
        // Forced to implement this, even though they don't have the authority!
        throw new NotImplementedException("Junior Developers cannot conduct reviews.");
    }
}
```

**The Problem:** `JuniorDeveloper` is forced to carry around the `ConductPerformanceReview` method that it doesn't use. This actually causes a **Liskov Substitution Principle (LSP)** violation as well, because passing a `JuniorDeveloper` to an `HR` method that expects an `IEmployee` and calls `.ConductPerformanceReview()` will crash the program!

## 4. Why is it needed using C# (The Fix & C# Benefits)
In C#, a class can implement multiple interfaces. This is the key to solving ISP. We break the "fat" interface into smaller, role-specific interfaces.

Here is the refactored, ISP-compliant C# code:

```csharp
using System;

// 1. Segregate the interfaces into specific roles
public interface ICoder
{
    void WriteCode();
}

public interface IMeetingAttendee
{
    void AttendMeetings();
}

public interface IReviewer
{
    void ConductPerformanceReview();
}

// 2. The Manager explicitly implements the roles they fulfill
public class Manager : ICoder, IMeetingAttendee, IReviewer
{
    public void WriteCode() => Console.WriteLine("Reviewing architecture...");
    public void AttendMeetings() => Console.WriteLine("Attending strategy meetings...");
    public void ConductPerformanceReview() => Console.WriteLine("Reviewing team performance...");
}

// 3. The Junior Developer ONLY implements what they actually do!
public class JuniorDeveloper : ICoder, IMeetingAttendee
{
    public void WriteCode() => Console.WriteLine("Writing C# code...");
    public void AttendMeetings() => Console.WriteLine("Attending daily standup...");
    
    // No more exceptions, no more wasted methods!
}
```

**C# Specific Benefits Here:** 
* **Multiple Inheritance of Interfaces:** C# doesn't allow a class to inherit from multiple base classes, but it does allow a class to implement endless interfaces (class MyClass : ICoder, IMeetingAttendee). This makes ISP incredibly natural in C#.

* **Granular Dependency Injection:** If a specific service in your C# backend only needs someone to write code, you can inject ICoder into its constructor. It doesn't need to know or care if the underlying employee is a `Manager` or a `Junior Developer`.

## 5. Implementation Guidelines

* **The `NotImplementedException` Red Flag:** Just like with LSP, if you find yourself writing `throw new NotImplementedException();` inside an interface implementation, you have almost certainly violated ISP.

* **Client-Specific Interfaces:** Interfaces should be designed based on what the client (the code calling the methods) needs, not based on what the class implementing it happens to have.

* **Keep them small:** An interface with 1 to 3 methods is usually a good sign. An interface with 15 methods is a giant red flag.
